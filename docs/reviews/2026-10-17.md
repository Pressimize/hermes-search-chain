# Review of 2026-10-17

Seven free models, run through the `opencode` client, and Claude reviewed the code, the scripts and the match between code and [design.md](../design.md). Every finding was checked against the code, with a script or test where possible, and against the source of Hermes Agent v0.21.6. The raw model answers are not in the tree; they are kept under the git tag `review-2026-10-17-raw`.

Result: eight fixes, one extension left out, and a list of rejected groups. The rejected list is meant for later reviewers: a point that belongs to one of its groups has been looked at and settled.

## Rejected

Grouped by topic. Letters are not stable across reviews.

### Engines (`engines.py`)

- **A. Limits and types of `limit` in the engine functions** (cap only for Parallel, no lower bound, no type check). Not reachable: the provider clamps `limit` to 1..20 first (A6), and Hermes always passes an integer. The engine functions are internal; S5 catches anything else.
- **B. Negative or huge `highlight_chars`.** The provider accepts only 1 to 6 digits (A1). A range is the operator's own business (D16).
- **C. Shape of 2xx replies:** one non-object in the result list makes the whole reply `malformed`; `excerpts` or `highlights` as a string; a parser that might not raise `RecursionError`. Settled by A4 (`test_malformed_reply`); the chain asks the next stage either way (K4). Hermes' own providers also treat `highlights` and `excerpts` as lists. The recursion test is green in CI on 3.11 and 3.14.
- **D. URL handling and numbering:** case, control characters, trailing blanks, renumbered `position`, redirects. S4: the URL is passed on as sent and Hermes checks URLs itself. The three APIs do not redirect; `test_only_2xx_is_a_reply` makes a 302 an error.
- **E. Result text not sanitised:** control characters, a key echoed in a hit, raw response text in the error detail. Titles and descriptions are third-party content that reaches the model as the provider sends it (section 10); Hermes marks search results as untrusted. S3 masks keys in error texts and logs, and L1 lists no results. The response text as detail is set by A4.
- **F. Details of `_detail`:** falsy values skipped, nested `message`, a list shown as a Python list. Checked: `{"error": ["a","b"]}` gives `HTTP 400 ['a', 'b']`, readable and harmless. Skipping an empty field gives a better reason than an empty string. No documented error body of the three providers is affected.
- **G. Empty error body gives `HTTP 500 ` with a trailing blank.** Wrong: `_error` normalises the whole text; checked, it gives `Exa: HTTP 500`.
- **H. Cost of reading and scanning the whole reply body; settings read on every call.** D16 (httpx holds the body before any cut) and D15 (several profiles in one process).
- **I. Engine result without `code` or `status` raises `KeyError`; `_error` with `key=None`.** Not reachable: an engine returns rows or an `_error` dict with both fields, and keys are always strings.
- **J. Key masking also hits parts of other words.** S3: every literal repetition from 8 characters is masked on purpose; a mangled word is better than a key in the log.

### Provider and manifest (`provider.py`, `plugin.yaml`)

- **K. `get_provider_env` may return `None` or an untrimmed value.** Wrong: in v0.21.6 it returns `(val or "").strip()`. The stub in `conftest.py` does the same.
- **L. Broad `except` clauses, lost exception texts, `_env` swallows every error, `KeyboardInterrupt`.** D16: the three broad clauses are deliberate (S3, S5, A4). Only the class name reaches error texts, so neither a key nor foreign text does. `KeyboardInterrupt` and `SystemExit` must not be caught.
- **M. One `httpx.Client` per call, no connection pool.** D14 (9 ms per client; idle connections are dropped after 5 s).
- **N. Pause table:** never pruned, `Retry-After` ignored, not thread-safe. D15 and K5: at most one entry per stage and key, a plain dict without a lock (concurrent calls set the same pause again), and after a 429 the chain moves on anyway.
- **O. No time limit for a whole search.** A0 and D13.
- **P. Interrupts:** silent fallback when `tools.interrupt` is missing; bare `"Interrupted"` without a prefix. S6: `tools.interrupt.is_interrupted` exists in v0.21.6 (`web_search_tool` imports it), and `"Interrupted"` is the text Hermes' own providers return.
- **Q. `requires_env` makes all three keys mandatory.** Wrong: v0.21.6 uses it only for install prompts, the catalog and `hermes doctor`. `is_available()` decides, and one key is enough (S2).
- **R. The pause reason is cut at 200 characters; "nearest hour" might mean banker's rounding.** K5 repeats the reply's error text, which A4 cuts to 200 characters. K5 and the tests round up from x.5.
- **S. `super().__init__()` missing; Hermes might instantiate with arguments.** `register()` instantiates the class itself, without arguments.
- **T. Misreadings in single answers:** a wrong remaining-time sum (after 81,001 s, 5,399 s remain; `_left` gives "1 h" as tested); missed trimming of settings (`" 1200 "` and `" V1 "` are tested and green); `surrogatepass` as a defect (it keeps such a key from aborting the chain, `test_key_that_cannot_be_encoded_fails_only_its_stage`); a pause end at `left == 0` (tested in `test_pause_after_quota_and_rate_limit`); a log detail without the provider name (the format of L2).

### Tests and style

- **U. Test environment:** `conftest.py` replaces the Hermes module, the proxy test connects to port 9, `request.extensions["timeout"]`, the `capture` helper, test seams (`transport`, `clock`), defaults bound at import time, shared `httpx.Response` objects. T1: the stub is intended, and T1 names the one test that opens a connection to a closed local port. `extensions["timeout"]` is a documented httpx request extension.
- **V. Style without a failure mode:** many positional arguments in `_post`, `STAGES` as a tuple, lines over 88 characters, a blank line after `except`. All calls are tested; `line-length = 120` and `ruff format --check` is green in CI.

### Scripts, CI and project file

- **W. `recompute.py`:** hard-wired denominators, `KeyError` or `ValueError` on changed data, duplicates, one seconds median over both blocks, `p 0.000`, `p 1.000` at 0:0. The data is published and fixed, and CI recomputes on every push (changed after this review: pytest runs the script, `tests/test_recompute.py`, instead of a separate CI step). The seconds median over both blocks matches the published times. `p 0.000` is rounding (`evaluation.md` says "below 0.001"); a sign test at 0:0 has p = 1 by definition. The character median was a real defect (S-01).
- **X. `live_check.py`:**
  - All `*_API_KEY` are removed so that keys come only from the profile's `.env` (docstring); settings are not promised.
  - A script without a UI cannot be interrupted, and `web_search_tool` always returns a JSON string in v0.21.6.
  - The pause after the last query keeps the pace across the three runs of T2, and each request takes time, so the rate stays below 8 per minute.
  - It targets Hermes Desktop on Windows and takes `HERMES_ROOT`; whoever sets the environment controls the process anyway. INFO logging must be on to see the line.
  - The claim that `paused for` hides stages is wrong: that text is only in the WARNING line (L2); the INFO line says `exa=paused`.
  - The `hermes_bootstrap` import before `.env` and `--break` worked as intended (validation.md, T2).
  - Only lines starting with `search-chain: ` are collected, so no `IndexError`; `keyless_rescue` is compared strictly with `false` on purpose (T2).
- **Y. CI and project file:** `> /dev/null`, duplicate CI runs, pinned `httpx`, missing `uv.lock`. T4 asks only that `recompute.py` runs in CI; duplicates cost CI time only (changed after this review: `push` triggers only for `main`, so a pull request runs once, and the separate `recompute.py` step with `> /dev/null` is gone because pytest runs the script). `httpx==0.28.1` is the version of Hermes v0.21.6 (comment in `pyproject.toml`). `uv.lock` is in the repo; it was not among the attachments.

## Method

The models first ran with shell access in the repository. Some read other models' answers in the working folder, and one compared the attachments with the working tree, so repeated mentions are no measure of weight. The review script was then changed to run each model alone in an empty folder outside the repo, with the attachments only and no shell, and all models were asked again on the same files.

The isolated answers were independent but shallower. They found V-01 (four times), V-04 and V-05, and neither E-01 nor S-01, which had been found by running code. T-01, T-02 and V-02 were not found either. A second opinion on code is worth most when the code is also run; both defects were confirmed that way.
