1. **`scripts/recompute.py:65` – potenzieller Bug.** `chars` wird fest auf `run2-main` gefiltert, während `seconds` in derselben Zeile (Zeile 64) über *beide* Blöcke gemittelt wird. Firecrawl existiert laut `data/provider-comparison/run2-results.csv` nur in `run2-extra`, also liefert der Generator leer und `median()` gibt `None` zurück: `python scripts/recompute.py | grep firecrawl` → `firecrawl   0  16  16  1.33 s  None chars`. Der im Dokument veröffentlichte Wert „3.900 (extra block)“ (`docs/evaluation.md:78`, Median über den Extra-Block = 3925) ist mit diesem Skript damit nicht reproduzierbar.

2. **`scripts/recompute.py:62-66` – Edge Case / irreführende Ausgabe.** Es werden nur Summen, keine Nenner gedruckt. Bei Firecrawl bedeutet die `0` in der Main-Spalte „nicht gelaufen“, nicht „0 richtig“ – im Output steht nicht unterscheidbar `firecrawl 0 16 16`. Das Dokument umgeht das manuell mit „not run“ (`docs/evaluation.md:72-73`), das Skript hat dafür keine Erkennung (`main_set` wäre 0 auch dann, wenn alle 55 Fragen mit 0 bewertet wurden).

3. **`scripts/recompute.py:48,58` – potenzieller Bug.** Die Nenner „of 55“, „of 10“, „main set of 55, extra block of 20“ sind fest verdrahtet statt aus den Daten abgeleitet (60 Zeilen pro Spalte, davon 5 ohne Wert). Löscht man eine `exa`-Zeile aus `run1-results.csv`, druckt das Skript `exa  54 54 …` unter der Überschrift „of 55“ und `main_set + extra` wird zu einer Summe zweier unterschiedlich großer Mengen, ohne dass ein Fehler entsteht.
